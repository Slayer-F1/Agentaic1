# مُنجِز — Munjiz
## مستند المشاركة الرسمي — تحدي ابتكار وكلاء الذكاء الاصطناعي

**المنصة:** n8n · **النموذج:** Google Gemini 2.5 Flash (الفئة المجانية عبر Google AI Studio) · **المشاركة:** فردية

---

## ١. نبذة عامة

«مُنجِز» وكيل معاملات ذكي واحد يُنجز الإجراءات الرقمية الاعتيادية للموظفين — إجازات، شهادات، مطالبات نفقات، صلاحيات أنظمة — محادثةً بالعربية، عبر ابتكارين مترابطين:

**أولًا: المهارات المحوكمة.** كل إجراء مؤسسي «مهارة» معتمدة بإصدار (الحقول المطلوبة، قواعد الأهلية نصًا، الخدمات المسموحة، سلسلة الاعتماد، سياسة التصعيد) مقترنة بملف خبرة يحدد شخصية الوكيل. تعيش المهارات في **جداول بيانات n8n** ويُحمّل الوكيل المهارة المطابقة لحظيًا عند كل طلب فيصبح خبير ذلك الإجراء: يجمع الحقول **بخيارات جاهزة للنقر** لا بأسئلة مفتوحة، يفحص الأهلية عبر الخدمات، يعرض بطاقة معاينة لا تُرسل إلا بتأكيد الموظف الصريح، وتمر معاملته بسلسلة اعتماد بشرية مع **تقرير مُعدّ للمعتمِد** يلخص تحققه من السجلات.

**ثانيًا: التعلّم المؤسسي المحوكم.** بعد أن يحصل الموظفون على إجاباتهم، تعمل «مراجعة ما بعد الدور» — وكيل ثانٍ مهمته الوحيدة تحسين المنظومة: يكتب وقائع دائمة في **ذاكرة** محدودة بميزانية أحرف صارمة (عند الامتلاء يُرفض القيد ويُجبر على الدمج أو الحذف)، و**يقترح** تحسينات على المهارات. الاقتراح لا ينفَّذ: يبقى معلقًا حتى يعتمده مالك الإجراء من لوحة الحوكمة، وعندها **يُكتب التحسين في نص المهارة نفسها ويرتفع إصدارها** — فتتحسن الإجراءات فعليًا مع بقاء القرار بشريًا بالكامل.

**جوهر الابتكار:** إضافة إجراء جديد = صف واحد في سجل المهارات ونص markdown — لا تعديل لأي تدفق. والحوكمة كود يُنفَّذ لا وثيقة تُنسى: بوابة خدمات موحدة تفرض قائمة الخدمات المسموحة لكل مهارة — بما فيها مهارة التعلّم ذاتها — وترفض ما عداها وتسجل كل استدعاء، بما فيه المرفوض، في سجل تدقيق دائم.

## ٢. المشكلة وأين تقع

كل جهة (حكومية أو خاصة) تقدم لموظفيها عشرات الإجراءات الاعتيادية عبر بوابات نماذج تقليدية: الموظف يبحث عن النموذج الصحيح، يخطئ في الحقول، يجهل قواعد الأهلية فيُرفض طلبه بعد أيام، والمعتمِد يقرأ نماذج خامًا بلا سياق، والإدارات تستهلك وقتها في الإرجاع والتصحيح والمتابعة اليدوية. وأتمتة هذه الإجراءات اليوم تعني بناء وصيانة نظام منفصل لكل إجراء — كلفة تجعل الإجراءات الصغيرة لا تُؤتمت أبدًا، والأنظمة التي تُبنى لا تتعلم من تشغيلها شيئًا.

**المستخدمون المستهدفون:** جميع الموظفين (مقدمو الطلبات)، المدراء ومعتمدو المراحل (المالية، أمن المعلومات)، والإدارات مالكة الإجراءات التي تملك مهاراتها وتعتمد تحسيناتها.

## ٣. البنية

| المكوّن | الوظيفة |
|---|---|
| **سجل المهارات (جداول n8n)** | `Skills` + `Profiles`: المصدر الوحيد للحقيقة بإصدارات وحالة اعتماد؛ مبذور من ملفات markdown المؤلفة في المستودع |
| **01 Main — المحادثة** | مصنّف نية ← تحميل المهارة والخبرة والذاكرة ← تركيب موجّه النظام ديناميكيًا ← وكيل Tools بذاكرة جلسة ← تدقيق حتمي لأيام العمل ← رد ببطاقات وخيارات |
| **01 Main — الاعتمادات** | قرارات بشرية فقط: تحقق من صفة المعتمِد، تقدّم السلسلة، تنفيذ الآثار (خصم رصيد، منح صلاحية) |
| **01 Main — حارس الإنجاز** | جدولة تلقائية: يقرر النموذج لكل معاملة متأخرة: تذكير / تصعيد / انتظار — بمسوّغ يُحفظ |
| **01 Main — المراجعة (التعلّم)** | وكيل ثانٍ بعد الخدمة: ذاكرة بميزانية 2200 حرف + اقتراحات تحسين معلقة؛ ميثاقه نفسه مهارة محوكمة لا يستطيع تعديلها |
| **02 Service Gateway** | كل استدعاء أدواتي يمر هنا: فرض allowed_services من السجل + تنفيذ الخدمات + سطر تدقيق لكل استدعاء (DENIED للرفض الحوكمي، ERROR للأخطاء) |
| 00 Data IO / 03 Error Handler | قراءة موحدة للجداول · معالجة الأخطاء |

**البيانات كلها داخل n8n** (جداول بيانات مدمجة): لا Google Sheets، لا خدمات خارجية، ولا اتصال شبكيًا وقت التشغيل — بيانات الاعتماد الوحيدة هي مفتاح Gemini في مدير n8n.

**الواجهة:** بوابة محادثة عربية أولًا (بمرآة إنجليزية كاملة): خيارات قابلة للنقر في المحادثة، بطاقات معاينة وتأكيد، «طلباتي» ببطاقات وخط زمني للاعتماد و**تنزيل الشهادات PDF بختم الجهة**، «الاعتمادات» بطاقات قرار يتصدرها **تقرير الوكيل للمعتمِد** مع حقل ملاحظة، و«الحوكمة» تعرض شريط التعلّم (عداد الذاكرة، المقترحات) واعتماد مقترحات التحسين وسجل المهارات المُصدَّر وسجل التدقيق.

## ٥. الأثر

- إجراء اعتيادي: من نموذج يُبحث عنه ويُخطأ فيه إلى محادثة بخيارات جاهزة لا تقبل طلبًا مخالفًا للسياسة أصلًا.
- المعتمِد يقرأ تقريرًا مُعدًّا (الموظف — الطلب — التحقق — التوصية) بدل نموذج خام: قرار في ثوانٍ بمعلومات كاملة.
- **كلفة أتمتة إجراء جديد ≈ صفر، وكلفة تحسينه أقل:** يقترح الوكيل التحسين من التشغيل الفعلي ويعتمده المالك بنقرة، فيرتفع إصدار المهارة — منظومة تتحسن كل أسبوع بدل أن تتقادم.
- امتثال قابل للتدقيق: كل استدعاء وكل قرار وكل رفض حوكمي وكل تعديل مهارة مسجّل بمسوّغه وصاحبه.

## ٦. الأمن والبيانات

مفتاح Gemini وحده في مدير بيانات اعتماد n8n (لا خدمات خارجية إطلاقًا) · جميع البيانات تركيبية موسومة «تجريبي» · مبدأ الحد الأدنى مفروضًا كودًا (allowlist لكل مهارة، ومهارة التعلّم محصورة في ثلاث خدمات) · لا تنفيذ لمعاملة دون تأكيد الموظف، ولا اعتماد إلا بشريًا، ولا تعديل لمهارة إلا باعتماد مالكها · الشهادات الصادرة موسومة «نسخة تجريبية» بعلامة مائية.

## ٧. الإفصاح

بُني بمساعدة أدوات ذكاء اصطناعي برمجية (مسموح ومشجَّع) · n8n (Sustainable Use) وجداول بياناته المدمجة · Gemini API المجانية · خط IBM Plex Sans Arabic (OFL) · لا قوالب n8n جاهزة — جميع التدفقات والمهارات أصلية لهذا المشروع · مفهوم «المهارات + الذاكرة + المراجعة اللاحقة» مستلهم من أنماط معمارية عامة في وكلاء الذكاء الاصطناعي مع حوكمة أصلية (الاعتماد البشري الإلزامي وسجل التدقيق).

# English Summary

**Munjiz (مُنجِز)** is ONE transactions agent that completes routine employee procedures — leave, certificates, expense claims, system access — conversationally in Arabic, built on two linked innovations.

**Governed skills:** every procedure is a versioned, approved skill (required fields, eligibility rules in plain language, allowed services, approval chain) living in **n8n data tables**. Per request the agent loads the matching skill and becomes that procedure's expert: it collects fields through **tap-to-answer choices** rather than open questions, verifies eligibility through services, shows a preview card submitted only on explicit confirmation, and attaches a structured **approver report** (employee — request — checks performed — recommendation) so the human decision takes seconds. Issued certificates download as **sealed, watermarked PDF documents**.

**Governed institutional learning:** after employees are served, a second reflection agent — itself constrained by a governed charter it cannot edit — writes durable facts into a hard-budgeted memory (2,200 chars; overflow forces merge-or-delete) and **proposes** skill improvements. A proposal stays pending until the procedure's owner approves it from the Governance view, at which point the rule is **written into the skill body and its version bumps** — procedures genuinely improve while every change remains a human decision with an audit trail.

Everything runs inside n8n: no external services, no network dependency at runtime, one credential (the Gemini key). A single **service gateway** enforces each skill's allowlist — including the learning skill's — logging every call, denials distinctly marked. All six agent criteria implemented and inspectable live. Deliverables: 4 importable workflows (10-file granular variant alongside), the skill library, a bilingual chat-first portal, one-command Docker stack with idempotent deploy script, synthetic seed data, setup guide, and a demo script.
