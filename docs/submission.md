# مُنجِز — Munjiz
## مستند المشاركة الرسمي — تحدي ابتكار وكلاء الذكاء الاصطناعي

**المنصة:** n8n · **النموذج:** Google Gemini 2.5 Flash (الفئة المجانية عبر Google AI Studio) · **المشاركة:** فردية

---

## ١. نبذة عامة

«مُنجِز» وكيل معاملات ذكي واحد يُنجز **جميع** الإجراءات الرقمية الاعتيادية للموظفين — إجازات، شهادات، مطالبات نفقات، صلاحيات أنظمة — محادثةً بالعربية، عبر ابتكار حوكمي بسيط: **المهارات المحوكمة**. كل إجراء مؤسسي هو ملف `SKILL.md` معتمد بإصدار في مستودع git (الحقول المطلوبة، قواعد الأهلية نصًا، الخدمات المسموحة، سلسلة الاعتماد، سياسة التصعيد)، مقترنًا بملف خبرة `PROFILE.md` يحدد شخصية الوكيل. عند كل طلب يصنّف الوكيل النية، يُحمّل المهارة الموافقة **لحظيًا من GitHub**، فيصبح خبير ذلك الإجراء تحديدًا: يجمع الحقول محادثةً، يفحص الأهلية عبر الخدمات، يعرض بطاقة معاينة لا تُرسل إلا بتأكيد الموظف الصريح، وتمر معاملته بسلسلة اعتماد بشرية. و«حارس الإنجاز» يفحص كل خمس دقائق المعاملات المتأخرة عن مواعيدها ويقرر بنفسه التذكير أو التصعيد.

**جوهر الابتكار:** إضافة إجراء حكومي جديد = كتابة ملف markdown واحد ودفعه إلى git — **لا تعديل لأي تدفق في n8n إطلاقًا**. الحوكمة ليست وثيقة تُنسى؛ هي الكود الذي يُنفَّذ: بوابة خدمات موحدة تفرض قائمة الخدمات المسموحة لكل مهارة وترفض ما عداها وتسجل كل استدعاء — بما فيه المرفوض — في سجل تدقيق دائم.

## ٢. المشكلة وأين تقع

كل جهة (حكومية أو خاصة) تقدم لموظفيها عشرات الإجراءات الاعتيادية عبر بوابات نماذج تقليدية: الموظف يبحث عن النموذج الصحيح، يخطئ في الحقول، يجهل قواعد الأهلية فيُرفض طلبه بعد أيام، والإدارات المقدمة للخدمة تستهلك وقتها في الإرجاع والتصحيح والمتابعة اليدوية للاعتمادات المتأخرة. وأتمتة هذه الإجراءات اليوم تعني بناء وصيانة workflow منفصل لكل إجراء — كلفة تجعل الإجراءات الصغيرة لا تُؤتمت أبدًا.

**المستخدمون المستهدفون:** جميع الموظفين (مقدمو الطلبات)، المدراء ومعتمدو المراحل (المالية، أمن المعلومات)، والإدارات مالكة الإجراءات (الموارد البشرية، المالية، تقنية المعلومات) التي تملك مهاراتها وتطوّرها.

## ٣. البنية

| المكوّن | الوظيفة |
|---|---|
| **سجل المهارات (GitHub)** | `registry/skills-index.json` + ملفات `skills/*.skill.md` و`profiles/*.profile.md` — المصدر الوحيد للحقيقة، بإصدارات ومراجعة تغييرات عبر git |
| **01 Chat Agent** | مصنّف نية ← تحميل المهارة والخبرة من GitHub ← تركيب موجّه النظام ديناميكيًا ← وكيل Tools بذاكرة جلسة ← تدقيق حتمي لأيام العمل ← رد JSON للبوابة |
| **02 Service Gateway** | كل استدعاء أدواتي يمر هنا: فرض allowed_services من السجل + تنفيذ الخدمات (أرصدة، سياسات، دليل أنظمة، إنشاء معاملة) + **سطر تدقيق لكل استدعاء** |
| **03 Approvals** | قرارات بشرية فقط: تحقق من صفة المعتمِد، تقدّم السلسلة، تنفيذ الآثار (خصم رصيد، منح صلاحية)، إشعار الموظف |
| **04 SLA Chaser** | كل ٥ دقائق يقرر النموذج لكل معاملة متأخرة: تذكير / تصعيد / انتظار — بمسوّغ مكتوب يُحفظ |
| **05 Dashboard API** | يخدم البوابة: الحالة الحية والمهارات (حية من GitHub) وسجل التدقيق |
| 00 Data IO / 06 Error Handler / 07 Demo Reset | قراءة موحدة · معالجة أخطاء · إعادة تهيئة العرض |

**الواجهة:** بوابة محادثة عربية أولًا (بمرآة إنجليزية): محادثة مُنجز مع بطاقات المعاينة والتأكيد، «طلباتي» بخط زمني لسلسلة الاعتماد وعرض الشهادات الصادرة، «الاعتمادات» صندوق قرارات المعتمدين، و«الحوكمة» تعرض سجل المهارات الحي من GitHub وسجل التدقيق بمرفوضاته.

## ٥. الأثر

- إجراء اعتيادي: من نموذج يُبحث عنه ويُخطأ فيه إلى محادثة دقيقتين لا تقبل طلبًا مخالفًا للسياسة أصلًا — فتختفي دورات الإرجاع والتصحيح.
- **كلفة أتمتة إجراء جديد ≈ صفر:** ملف markdown واحد يخضع لمراجعة git، فيصبح تعميم الأتمتة على «كل» الإجراءات الاعتيادية ممكنًا اقتصاديًا لأول مرة.
- امتثال قابل للتدقيق: كل استدعاء بيانات وكل قرار وكل رفض حوكمي مسجّل بمسوّغه.
- لا معاملة تعلق: حارس الإنجاز يطارد الاعتمادات المتأخرة تلقائيًا.

## ٦. الأمن والبيانات

مفاتيح Gemini وSheets وGmail في مدير بيانات اعتماد n8n حصريًا · جميع البيانات تركيبية موسومة «تجريبي» · مبدأ الحد الأدنى مفروضًا كودًا (allowlist لكل مهارة) · لا تنفيذ لمعاملة دون تأكيد الموظف، ولا اعتماد إلا بشريًا عبر سلسلة محددة · صلاحية admin مؤقتة إلزاميًا بنص المهارة.

# English Summary

**Munjiz (مُنجِز)** is ONE generic transactions agent that completes routine employee procedures — leave, certificates, expense claims, system access — conversationally in Arabic, governed by an innovation we call **governed skills**: every procedure is a versioned, approved `SKILL.md` in a git repository (required fields, eligibility rules, allowed services, approval chain, escalation policy) paired with a `PROFILE.md` persona. Per request, a router loads the matching skill live from GitHub, the agent becomes that procedure's expert, collects fields conversationally, checks eligibility through services, and shows a preview card that is only submitted on the employee's explicit confirmation — then human approvers advance the chain, and a 5-minute SLA chaser autonomously decides to remind or escalate stale approvals.

The governance is executable, not documentary: a single **service gateway** enforces each skill's service allowlist (denials are logged and visible in the audit view — ask the certificate agent for a leave balance and watch governance refuse), and writes an audit row for every call. **Adding a new government procedure = pushing one markdown file** — zero n8n changes, demonstrated live in the demo. All six agent criteria implemented and inspectable. Deliverables: 8 n8n workflows, the governed skill library, a bilingual chat-first portal, synthetic seed data, setup guide, and an 8-minute demo script.
